# خطة الحفاظ على تقدم التلميذ

## المبدأ
بيانات التقدم ملك للمتصفح/التلميذ وليست جزءاً من بيانات الكتاب. يجب عدم حذف مفاتيح التخزين الحالية أو إعادة استخدامها بمعنى مختلف أثناء الانتقال.

## التصميم المستهدف
يُحفظ التقدم الجديد في مفتاح مستقل ذي مساحة أسماء وإصدار، مثلاً:
`taalam:progress:v1:<bookId>`

هيكل السجل المقترح:
```json
{
  "progressSchemaVersion": 1,
  "bookId": "reading",
  "contentVersion": "1.0.0",
  "updatedAt": "2026-11-22T10:00:00.000Z",
  "completedLessons": ["lesson-01"],
  "activityStates": {
    "activity-01": { "status": "completed", "attempts": 2 }
  },
  "lastPosition": {
    "unitId": "unit-01",
    "lessonId": "lesson-01",
    "activityId": "activity-01"
  }
}
```

## قواعد التوافق
1. **عدم المسح:** لا يمسح النظام مفاتيح localStorage القديمة أثناء الترحيل.
2. **قراءة آمنة:** يُقرأ التقدم القديم فقط بعد تحديد مفاتيحه الفعلية ودلالاتها من الشيفرة الحالية.
3. **نسخ قبل التحويل:** ينشأ snapshot احتياطي للمفاتيح القديمة قبل أي تحويل.
4. **ربط صريح:** لا يمكن تحويل تقدم درس قديم إلى درس جديد إلا بوجود جدول mapping معتمد من المالك.
5. **لا تخمين بالترتيب:** لا تربط الدروس بحسب رقم الفهرس أو العنوان وحده.
6. **تكرار آمن:** تشغيل الترحيل أكثر من مرة لا يكرر السجلات ولا يستبدل تقدماً أحدث.
7. **تحقق بعد التحويل:** مقارنة عدد الدروس المكتملة وآخر موضع محفوظ قبل وبعد الترحيل.
8. **رجوع:** يبقى مصدر التقدم القديم محفوظاً حتى نجاح الاختبار واعتماد الانتقال.

## قرار المرحلة الثانية
لم يتم تنفيذ مهاجر فعلي بعد؛ لأن ذلك يتطلب فحص مفاتيح التخزين الحالية وسلوكها في الصفحات الست، وتحديد ما إذا كانت المفاتيح مشتركة أو منفصلة. النموذج التجريبي يستخدم مساحة أسماء تجريبية منفصلة ولا يقرأ أو يكتب مفاتيح الكتب الحالية.

## خطة التنفيذ قبل الإطلاق
- جرد مفاتيح التخزين القديمة لكل كتاب.
- توثيق شكل البيانات القديمة.
- إعداد mapping للمعرّفات القديمة والجديدة عند توفر المحتوى.
- اختبار ترحيل على نسخة احتياطية من بيانات تجريبية.
- إضافة تصدير/استيراد احتياطي للتقدم إن أمكن.
- عدم إطلاق الترحيل قبل اختبار الرجوع.
